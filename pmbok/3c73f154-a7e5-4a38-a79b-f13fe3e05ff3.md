# Lesson — Mocked-domain unit tests blind to resolver regressions

## Insight

В feature, где production input проходит multi-stage transformation (RDF triple store → CommandResolver.loadGroundingDefinition → domain `GroundingDefinition` object → GroundingExecutor.executeCreateInstance), unit-tests мокированные на уровне domain object **пропускают resolver stage целиком**.

Concrete instance: `GroundingExecutor.test.ts:925-1180` (247 lines, 9 tests на copy-from-target + linkBackProperty block) builds `grounding` mock object с already-parsed bare values (`linkBackProperty: "ems__Effort_parent"`). Tests pass. Production runtime получает grounding из RDF — где value хранится как `"[[<UID>|ems__Effort_parent]]"` literal. `CommandResolver.getObsidianName` возвращает raw literal. Domain object имеет `linkBackProperty = "[[<UID>|ems__Effort_parent]]"` (wrapped). Executor использует это как property name — ничего не находит, fallback на `exo__Asset_source`.

**Все 35+ CI checks PR #3105 green. v15.173.0 published. Feature broken в production. Discovered только при e2e manual test в real Obsidian 7 days later.**

## Context

Surrounding Progress Log line из `05cca8cf-...` (Task 5.1 Progress Log 2026-05-14T10:44):

> **Slepая зона:** все 9 unit-тестов проходят (используют моки `grounding` объектов с уже-распарсенными bare values, пропуская RDF→Grounding resolver stage). Integration-test между `CommandResolver.resolve → GroundingExecutor.execute` отсутствует — это и есть root cause промаха.

## Applicability

**Affected pattern:** Любая feature с pipeline `<external data source> → <parser/resolver> → <domain DTO> → <service>`.

**Mitigation pattern:**

1. **При создании resolver-executor pair — обязательно ≥1 integration test** exercising full pipeline (real triple store → real resolver → real executor) на каждый new property/behavior, не только unit на executor с мокированным DTO. Cost ≈ 50-100 LOC за fixture; катastrofично дешевле чем post-ship hotfix release.
2. **При adding new RDF property, проходящего через resolver:** explicit unit на resolver behavior (`getObsidianName`, `getLiteralValue` и аналоги) с **literal containing wikilink wrapper** в качестве input. Это catches «raw literal returned without normalization».
3. **CI red-line:** integration test directory `tests/integration/<domain>/<pipeline>.test.ts` должна существовать как **must-have**, а не «маленькая зона coverage gap accepted».

**Counter-evidence required для skipping:** только если feature has ZERO chance прохода через transformation pipeline (e.g., direct constant write).
